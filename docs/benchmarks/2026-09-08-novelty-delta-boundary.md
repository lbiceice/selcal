## Strongest adverse case

The core operations cannot themselves be sold as new statistical methods. The IDTxl 1.6.0 documentation's executable source describes `max_statistic` as comparison against surrogate maxima across remaining candidates. SciPy's current `permutation_test` accepts a callable statistic and applies the Monte Carlo numerator/denominator plus-one convention. Root directly retrieved these primary sources on 2026-09-08:

- [IDTxl max_statistic source](https://pwollstadt.github.io/IDTxl/html/_modules/idtxl/stats.html#max_statistic).
- [SciPy permutation_test documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.permutation_test.html).

These are source-document inspections, not executions of these competing tools, a systematic search of all tools, or full-text SoftwareX exemplar cards. Neither source establishes that SelCal's entire operating contract is duplicated, and unknown competitor failure/replay behavior must remain unknown.

## Strongest positive case

The actual SelCal public path exposes an explicit scientific plan, a frozen common support, full candidate scans, labelled transformations, full reselection, retained failed positions and the planned finite denominator. These together make a concrete audit/reuse target. A separate scalar implementation now provides a small diagnostic fault boundary independent of the production statistic and selector.

The disclosed Pearson counterexample (full reselection 3/6 versus fixed-candidate 2/6) verifies a necessary operation, not a performance advantage over competent competing software. It is a negative control, not the comparator arm.
